# Week 5 — Simple Lock

TypeScript contract source lives in `contracts/simple-lock/src/index.ts`, outside the React portal. It runs in CKB JS VM; Node.js does not validate the on-chain lock.

## Reproducible build and tests

Prerequisites: Node.js 22+, OffCKB CLI, and native ckb-debugger 1.1.1. Install the debugger with `offckb install ckb-debugger` and put it on PATH, or set `CKB_DEBUGGER` to its executable path. On Windows, OffCKB normally installs it under `%LOCALAPPDATA%/offckb-nodejs/Data/tools/ckb-debugger.exe`.

From this directory:

```sh
npm ci
npm run typecheck
npm test
```

`npm test` bundles the source with the lockfile-pinned esbuild, compiles `dist/simple-lock.bc` using the packaged JS VM, and runs eight complete transaction fixtures through the native CKB debugger. Build only: `npm run build`. Both build and tests respect `CKB_DEBUGGER`. Generated bytecode and fixtures are ignored by Git.

Debug the exported fixtures after running the tests:

```sh
ckb-debugger --tx-file build/correct.json --script-group-type lock --cell-type input --cell-index 0
ckb-debugger --tx-file build/incorrect.json --script-group-type lock --cell-type input --cell-index 0
```

Expected run results: 0 and 7. Tests also cover missing and empty witnesses (6), malformed args (5), oversized preimages (8), a preceding unrelated input, and two inputs sharing a lock group.

## Deploy and prove commitment

Start `offckb node` in a separate terminal. Keep it running. Then, from this directory:

```sh
offckb system-scripts --output deployment/system-scripts.json
npm run deploy
npm run export:metadata
node scripts/verify-devnet.mjs --address
# Use the printed address in the next command:
offckb deposit <printed-address> 200
# Wait for the funding transaction to commit, then:
npm run test:devnet
```

Deployment uses OffCKB's built-in local development account. No key or seed is accepted by these project scripts or stored in this repository. The verification preimage `CellRoute Week 5` is a public test fixture, not a private key. The integration test returns capacity to the deployer's lock, asserts the node's rejection codes, waits for `committed`, and writes `deployment/week5-evidence.json`.

`deployment/scripts.json` contains the bytecode code hash and code OutPoint. `deployment/simple-lock.devnet.json` adds genesis identity and the JS VM dependency. `export:metadata` verifies the live bytecode before copying public metadata to `../portal/public/simple-lock.devnet.json`. Re-export after redeployment or resetting Devnet; never reuse stale OutPoints. Rebuild the portal after changing metadata.

## Portal

From `../portal`, run `npm ci` and `npm run dev`. Open `/simple-lock` (sidebar: Developers → Simple Lock Lab). The lab has its own local RPC client with no public-network fallback. For wallet funding, choose **OffCKB Devnet** in the connector, or start Vite with `VITE_CKB_NETWORK=devnet`. The wallet must support the selected local chain and have local funds. Terminal funding via `offckb deposit` works without a wallet.

1. Enter a preimage (1–1024 UTF-8 bytes) and derive the address; save the digest and preimage yourself.
2. Fund 200 CKB with a connected Devnet wallet, or copy the displayed deposit command.
3. Once funding commits, refresh live capacity and select the protected Cell.
4. Enter a recipient address and the original preimage. Construct and review the transaction.
5. Submit the unlock and check its transaction status until `committed`.

One plain capacity Cell is consumed per unlock; the fee is 0.001 CKB. Typed Cells and Cells carrying data are excluded. Before funding or unlocking, the lab verifies genesis identity, live dependencies, and code hashes. A wrong-chain wallet is rejected. An unlock needs no wallet signature: the raw witness is the preimage. Inputs are rechecked for liveness before submission.

## Contract encoding

Lock `codeHash` / `hashType` refer to **CKB JS VM**. Its args are:

```text
0000 | bytecode data hash (32 bytes) | 04 (data2) | preimage digest (32 bytes)
```

The preimage digest is 32-byte BLAKE2b with CKB personalization `ckb-default-hash`. It is not SHA-256 or unpersonalized BLAKE2b. The first group-input witness contains raw UTF-8 bytes, not Molecule WitnessArgs. Both the VM code Cell and the bytecode Cell must appear in `cellDeps`.

This is an educational bearer hash-lock. It does not bind a signature, recipient, or transaction hash. Anyone who learns the preimage can spend any Cell using the same lock, and submission publicly reveals the preimage. Use local Devnet funds only.
